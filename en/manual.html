User manual · v1.7.6 · macOS

VAREC — User manual

The official documentation for VAREC 1.7.6, the professional multitrack field recorder for macOS. This manual covers every feature of the application — from installation to take playback, by way of timecode setup, the analysis tools and sound report generation.

1. Overview

VAREC is a multitrack audio recorder built for sound professionals working in the field: music and live capture, events, theatre, film, documentary and post-production. The application works through your Mac's CoreAudio audio interface and takes full advantage of both Apple Silicon and Intel x86_64 architectures.

The interface is designed to stay minimal and readable on set, while exposing the professional features you can't do without: external timecode, stereo pairs, BWF/iXML metadata, redundant recording, take playback, exportable sound reports, cloud upload and reusable project files.

Key features

  • Multitrack capture of up to 512 channels simultaneously (depending on the CoreAudio interface), as multi-mono or as a polyphonic file
  • 24-bit PCM WAV, 32-bit float WAV and RF64 formats (files > 4 GB without splitting)
  • Sample rates from 44.1 kHz up to 192 kHz
  • Timecode sources: Time of Day, LTC (automatic input search) and Tentacle Sync E (Bluetooth LE), frame rates up to 60 fps
  • Simultaneous multi-disk recording (true real-time redundancy, not a post-recording copy), with the destination checked before every take
  • TAKES tab: takes sorted by scene, circled / false start status, playback with waveforms and notes on a TC timeline
  • Auto start at a scheduled time or on signal detection
  • Complete BWF / iXML metadata (scene, take, notes, engineer, track list)
  • Fader mode: faders, pan and recording of a stereo MAIN MIX
  • PDF / CSV Sound Report + email sending with attachments
  • Automatic upload to SwissTransfer, Smash, Dropbox or Cloudflare R2
  • Instant Peak / RMS+PPM VU meters with configurable peak hold
  • Analysis tools: LUFS loudness (EBU R128 / BS.1770-4), spectrum, spectrogram, peak, phase alignment — in a detachable window
  • Live waveforms while recording, with range playback and annotation
  • MIDI mapping for transport and faders
  • Interface in French, English and German
  • Crash Recovery: WAV headers written continuously, no corrupted files in the event of a power cut

2. Installation

System requirements

  • macOS 12 Monterey or later
  • Apple Silicon (M1, M2, M3, M4) or Intel x86_64
  • A CoreAudio-compatible audio interface (built-in or external)
  • 4 GB of RAM minimum (8 GB recommended beyond 64 channels)
  • Enough free disk space — a fast drive (internal SSD or external USB 3 / Thunderbolt SSD) is strongly recommended

Installation

  1. Download the DMG that matches your Mac — Apple Silicon or Intel — from the Download page. The DMGs are Developer ID signed and Apple notarized (Gatekeeper ✓).
  2. Double-click the DMG, then drag VAREC.app into the Applications folder.
  3. On first launch, macOS asks for microphone access: accept. Bluetooth access is only requested if you use a Tentacle Sync E.
  4. The session creation window opens: see §3 Quick start.
Permissions. On macOS, microphone access must be allowed in System Settings → Privacy & Security → Microphone. Without it, VAREC will not see any input channel. To record to an external drive or a protected folder, also allow VAREC under Files and Folders.
Tip. For sessions with a large number of channels, connect your audio interface before launching VAREC so that CoreAudio exposes it from startup. If the interface is connected afterwards, use the 🔍 button in Settings → Audio to run detection again.

Updates

At launch, VAREC checks whether a newer version is available and shows how many versions separate you from the latest one. The What's new window details the changes version by version, newest first — the five most recent are expanded, and a link leads to all the notes beyond that — with a Download button. Install the new version over the old one: projects and settings are kept.

3. Quick start

Beta. VAREC is in beta testing: every feature is unlocked free of charge, with no activation and no account. The loading screen says so, and the License menu shows “Beta version — all features active”. Please report any issue via Help → Send Crash Report.

On first launch, or via Session → New Project… (⌘+N), the creation window offers:

First recording

  1. PATCH tab: check the input interface and assign channels to physical inputs (⟵ Straight for a 1:1 patch).
  2. REC tab: add channels with T (⌥+T for a stereo channel, ⌘+T for batch creation) and arm them with the R button.
  3. In the bottom bar, check the FORMAT card (recommended: 48 kHz / WAV 32F, poly for post) and the ● destination card. Add a backup drive with ＋ Drive if needed.
  4. Press Space or click REC. A second Space splits the take; the ■ button (or Esc held for 3 s) stops it.
  5. Open the TAKES tab (⌘+3) to find and play back the take.
Automatic saving and resume. The project is saved in the session folder when it is created, when the application closes and whenever takes change (notes, status, scenes, cloud links). At launch, VAREC reopens your last session directly (project, settings, faders, eco mode, latency compensation) without going through the welcome screen.
Startup. Opening the audio interface at launch never blocks the application, including on a Dante network: an interface that does not respond is cleanly refused, without freezing VAREC. VU meters are live as soon as the app opens, without arming anything.

Guided tour

A 17-step guided tour (Help → Tour Guide) walks you through the application: REC button, channels and VU meters, solo view and analysis, waveform and playback, timecode, monitoring, tabs, settings cards, drives / split / false take, notes, modes, notifications, settings, sound report and cloud.

  • Esc closes the tour, the arrow keys navigate. During a recording, Esc does not trigger a stop.
  • A step whose target is missing from your setup is simply skipped. The bubble stays inside the window even on a small screen or with a large font size.

Turn on Help → Contextual help (hover) to show an explanatory bubble when hovering over controls.

Themes & fonts

The View → Theme menu (or Settings → Theme) offers five looks:

  • Dark — the default, optimised for night shoots and long reading sessions.
  • Light — suited to daytime indoor use.
  • Minimal — greyscale only.
  • OLED — pure black to save battery on OLED displays.
  • High contrast — maximum legibility in direct sunlight.

Four font families are available via View → Font: System, Mono, Rounded, Serif. Settings → Theme also sets the font size (Small, Normal, Large, XL), corners (Standard, Rounded) and the interface language — French, English or German, menus included.

5. Audio interfaces & patch

VAREC relies on CoreAudio: any Mac-compatible interface can be used, including Dante Virtual Soundcard, RME MADI, Focusrite Red, etc. The input interface is chosen in the PATCH tab, the DEVICES card or Settings → Audio.

Selection

  • Input interface — the one whose channels you are going to record.
  • Output interface — the destination for headphone / control-room monitoring. On an interface with more than two outputs, choose the pair used for monitoring (1-2, 3-4…): it is remembered per interface. With no output interface selected, nothing is played at all — sound no longer falls back to the Mac's default output.
  • Sample rate — AUTO to use the native rate, or a forced value. The menus only list the rates actually accepted by the interface, as reported by CoreAudio: on a fixed-48 kHz interface (an Allen & Heath SQ, for example), 44.1 and 96 kHz are simply not offered.
  • Buffer — 128 to 8192 samples, via the BUFFER card. Increase it if you notice xruns (dropouts).
Changing the sample rate. The setting targets the interface by its UID rather than its name, and reads the value back after writing it: a silent refusal by the driver is reported as such, instead of being announced as a success followed by an unexplained return to the previous rate.

Patch

The PATCH tab shows a grid: one row per channel, one column per physical input. Click a cell to assign the channel to that input.

  • ⌘+click, drag, then release — diagonal assignment of several channels.
  • ⟵ Straight — 1:1 patch; ✕ Clear — clears the whole patch.
  • Channel names can be edited directly in the grid; Batch opens batch creation.
  • The patch is locked while recording.

On REC, if armed channels are not assigned to any input, VAREC offers to disarm or keep them. Channels patched beyond the interface's inputs are reported in a single message giving their number and names.

Missing or slow-to-respond interface

At startup as when switching interfaces, VAREC waits — several attempts — instead of giving up at the first refusal. This helps USB, Thunderbolt or Dante interfaces that are slow to sync.

  • The interface is remembered by a stable key, not by its position in the system list. VAREC therefore never restores an interface other than yours without telling you.
  • If the expected interface is missing, VAREC starts on the first available one and tells you clearly, naming it.
  • If the new interface does not respond, VAREC returns to the previous one keeping patch and arming.
  • A project prepared on a large interface opens on a smaller one: the monitoring channel count adapts to the interface actually in use.
While recording. The input interface, sample rate, buffer and patch are locked. The monitoring output, however, can be changed on the fly, even mid-take, without touching the recording. Arming or disarming a track no longer restarts the audio engine: the other channels' VU meters keep running.
Safe opening. Every interface is pre-tested before opening: an interface that does not start (Dante Virtual Soundcard with no clock or network, for example) shows a clear message without ever freezing the application. Bluetooth audio devices (AirPods, etc.) are not supported for recording — their latency and clock make them unsuitable for multitrack work.

6. Multitrack recording

Arming channels

Click the track's R button, or press A or R, to arm a channel. Only armed channels produce an audio file. ARM ALL, above the tracks, arms everything; with no selection, A and R apply to every channel.

Starting a take

Press Space or click the red REC button. Just before, VAREC checks the destination: folder exists, volume mounted, writing possible. If it fails, no take starts and a window offers to choose another folder, record to the Desktop or cancel (see §10). The counter then starts and the WAV files are written continuously to every active drive.

The timecode stamped into the files is that of the first sample actually recorded, not the moment REC was pressed (audio starts 10 to 40 ms later); with LTC, frames are dated to the sample.

Split, Stop & False Take

  • Split — a second Space while recording cleanly closes the current files and opens new ones, without interruption. The take number increments and each file keeps its own timecode, number and notes.
  • Stop — the ■ button or Recording → Stop, with confirmation. From the keyboard: hold Esc for 3 seconds (a progress bar appears). WAV headers are finalised with the actual size.
  • False Take (✕) — stops the take after confirmation and marks it as a false start: the files get the _FALSE suffix and the take is flagged in the TAKES tab and the Sound Report.
  • Panic (⌥+P) — immediately finalises every file in case of a critical problem. A last resort.
  • Reset Peaks (⌥+R or the ↺ PEAK button) — resets the VU meter peaks.

Restarting REC right after a Stop is fine: VAREC waits until the previous take is fully closed — a few tenths of a second at most — so that no file is left without a header.

Auto start

The ⏱ button in the top bar arms a trigger:

  • Scheduled time — start time and, optionally, end time.
  • Signal on stereo track — the take starts when the level of an armed stereo track exceeds a threshold in dBFS. Stopping is manual (single take), or automatic after an adjustable silence duration: VAREC then re-arms for the next take.

Pre-roll is set in the same window, to keep the attack that precedes detection. While a trigger is armed, the Mac does not go to sleep from inactivity (closing a laptop lid still puts it to sleep). An armed trigger is never kept when the application is relaunched.

Pre-roll

A 2, 5 or 10-second pre-roll can be enabled in Settings → Record. When you start a take, VAREC includes the seconds preceding the trigger (captured continuously in a circular buffer).

Auto Peak Marker

When the option is ticked in the Recording menu, every peak that reaches 0 dBFS during the take adds a TC-stamped note naming the channel, including in multi-mono. These markers appear as a red dot on the relevant track in playback, and in the Sound Report.

After the take

Files are analysed on stop: those whose peak stays below –72 dBFS (channel with no signal) are prefixed _VIDE_ and listed in a summary window.

Live waveforms

While recording, VAREC draws the waveform of each armed channel at the source, directly from the incoming audio. No disk read-back or decoding happens during the take, and capture is never touched. A multi-resolution cache keeps long takes light.

  • The “〜” button or the W key shows one waveform lane per armed channel, with a translucent VU meter on top. The selector next to it sets the displayed duration: 5 s, 10 s, 30 s (default) or the whole take.
  • Stereo pairs show both sides separately (L above R in horizontal view), at the same width as a mono channel.
  • Channels that are patched but not armed show their live level as a greyed-out VU.
  • In the solo panel, the interactive waveform is drawn from the start of the take, below the analysis tools. Select a passage to play it back (▶ Réécouter) or add a note to it (📝 Note): the range is written as a timestamped note in the iXML <NOTE>. Playback respects the state of the monitor output. During selection, the waveform freezes to make spotting easier; Esc or a single click resumes the live view.

Audio formats

File mode

  • MONO (multi-mono) — one WAV file per armed channel; a stereo pair gives a stereo file with the _STEREO suffix.
  • POLY — a single multichannel file holding every armed channel, in track order. The recommended mode for film and post.

File naming

Files are written to {location}/{project}/{scene}/. With no template, they are named Project_T001_CH01_Name.wav. In the METADATA tab, a custom template is built from tokens, with a live preview:

TokenValue
{projet}Project name
{scene}Current scene (e.g. S01A)
{take}Take number on 3 digits (001)
{ch}Channel number on 2 digits (03)
{nom}Channel name
{date}Today's date (YYYYMMDD)
{ingenieur}Sound engineer's name

Special characters are replaced with _. A channel renamed during a take keeps its new name in the metadata.

Take numbering per scene. The take number belongs to the current scene: on every scene change, VAREC scans the actual folder on disk and resumes at the highest number + 1. Numbering therefore survives going back to a previous scene and reopening the project. As long as no scene has been entered, no placeholder scene is injected into the file name and those takes are labelled NO SCENE in the Sound Report.

BWF / iXML metadata

Every file automatically includes:

  • BWF timestamp (OriginationTime, OriginationDate)
  • Start timecode and frame rate (TimeReference) — pre-roll is taken into account, with no offset at conform in post-production
  • Scene, take, notes
  • Name of each track in iXML/TRACK_LIST — both channels of a stereo pair and of the MAIN MIX are declared
  • bext loudness fields compliant with EBU 3285 (“not set” rather than 0 LUFS when no measurement is available)

Automatic split

To avoid oversized files, VAREC can automatically split each take according to a per-format threshold, set in Settings → Record → Auto split:

FormatDefaultOther choices
WAV 242 h (≈ 1 GB / channel)Off, 1 h, 4 h, 2 GB max, 4 GB max
WAV 32F1 h 30 (≈ 1 GB / channel)Off, 1 h, 3 h, 2 GB max, 4 GB max
RF6424 hOff, 4 h, 8 h, 100 GB max
4 GB safeguard. For non-RF64 WAV formats (the format's technical limit is 4 GB), VAREC automatically triggers a safety split before reaching the limit, with byte-accurate detection. No take is lost to a size overflow. The MAIN MIX file (fader mode) and the copies on backup drives follow the same split.

7. Stereo, groups & faders

Per-channel controls

ControlEffect
R (A or R)Arms the channel for recording.
MUTE (M)Removes the channel from monitoring (recording continues if armed).
SOLO (S)Isolates the channel for monitoring and opens its analysis panel. Several solos add up.
NameDouble-click to rename (used in the file name and in iXML).

Select a track with a click, a range with ⇧+click, everything with ⌘+A. With no selection, A, R and M apply to every channel; S requires a selection. Right-clicking a track opens a menu: arm, mute, solo, link as stereo, select all, rename, change group, new group, delete.

✕ MUTE and ✕ SOLO (at the top of the channel area) clear every mute or every solo in one click, with immediate effect on monitoring. ✕ SOLO also releases the analyser, which no longer keeps running in the background on the previously soloed channel.

Stereo pairs

Three ways to create a stereo pair:

  • ⌥+T adds a stereo channel directly.
  • Select two channels, right-click → ⇌ Link as stereo.
  • When two channels receive a strongly correlated signal, VAREC offers to create the pair (automatic detection).

A pair takes up a single track with two L / R meters and, in multi-mono, produces an interleaved stereo file with the _STEREO suffix. Mute, solo and fader apply to both sides, and soloing a pair is heard in stereo. The ⊠ SÉPARER button, shown when hovering the track, splits the pair. A pair counts as two channels in the diagnostics and disk-space estimates; pairs can be multi-selected and grouped with mono tracks.

Groups

To gather contiguous channels (every track of a drum kit, of an actor…) under a shared colour bar:

  1. Select the channels (click + ⇧).
  2. Press ⌘+G — or right-click → ＋ New group… to choose name and colour.
  3. Double-click the group label to rename it; right-click → ⇄ Change group to move a track into it.

Each group header carries its own ARM, MUTE and SOLO buttons, applied to all its channels. The group colour carries over to take playback.

Fader Mode & MAIN MIX

Enabled when creating the session or in Settings → General, fader mode adds to each channel:

  • a fader (double-click: back to 0 dB) — dragging a selected channel's fader moves the whole selection while keeping the offsets; a stereo pair has its own fader;
  • a pan control (double-click C: back to centre); on a stereo pair it acts as a balance. At centre, the level is the same as in earlier sessions.

A MAIN MIX track appears at the bottom of the list: it is recorded to a separate stereo file, computed exactly like what you hear. The channels themselves are still recorded without fader, at their input level. Fader positions are stored at the start of every take.

Solo & monitoring

Solo is a temporary listening state. It is not saved in the session file: a session never opens with a soloed channel.

  • A channel that is both muted and soloed stays silent, in every mode.
  • Pairing a soloed channel as stereo moves the solo onto the left channel.
  • Leaving fader mode releases group solos.
  • The ⊕ Phase tool puts its reference channel in solo — with a visible indicator — and releases it however the panel is closed.

8. Take notes

Press N or click the NOTES card to open the NOTES — CURRENT TAKE panel. While recording, the note is stamped with the timecode of the moment the panel opens.

  • ↵ Return — saves the note and closes the panel.
  • ⇧+↵ Return — new line without closing.
  • The current take's note history is listed above the input field.

Notes are attached to the take in the project file, written to the iXML of every file concerned, shown on the playback timeline and included in the Sound Report. Auto Peak Marker peak markers are added to them automatically.

After the take, notes are edited from the TAKES tab (see §9), where N also adds a note at the playback position.

9. Takes, scenes & playback

The TAKES tab (⌘+3) lists the project's takes, grouped by scene, each with its start timecode, duration, notes and track count. The list is rebuilt from the recorded files: it is intact after a relaunch (↻ button to re-read the folder). During a recording, the list is frozen.

Status and notes

  • Status dot — a click cycles the take from circled to false start, then to no status. The status appears in the Sound Report.
  • Notes — right-click a take's notes cell to edit all its notes: one note per line; a timecode at the start of a line ([10:37:22:00]) places it on the timeline.

Scenes

Scenes are managed here, with the green + NEW SCENE button: enter its name and take numbering restarts at T001. Created during a recording, the new scene applies to the next take. Each scene has its own sub-folder in the project folder.

Playback

Clicking a take displays it in place of the live tracks: every track with its full waveform, laid out like the REC waveform view (groups, colours, VU meters), under a timecode timeline carrying the notes. Automatic peak markers show as a red dot on the relevant track. The REC button turns into PLAY.

Playback goes to the monitoring output, following the same rules as monitoring: monitor on or off, solo, default track, volume. In fader mode, the recorded MAIN MIX is played if it exists; otherwise the tracks are mixed with the faders as they were at the start of the take. Live monitoring is muted while playing.

REC always wins. A recording started by any means (button, MIDI, auto start) first leaves playback: REC is never blocked.

10. Simultaneous multi-disk

VAREC can write the same WAV file to several drives at once. This is true real-time redundancy — not a copy made afterwards.

Destination and backup drives

In the bottom bar, the card marked ● (red outline) is the recording destination: click it to change folder. The other cards are backup drives: when ticked, they receive a simultaneous copy of every take. Each card shows free space and remaining recording time, updated during the take.

  • ＋ Drive — adds a backup drive by choosing its folder; it is checked before being accepted.
  • Right-click a card — change the folder (the action says whether it is the destination or a backup), reveal in Finder, rename, delete.
  • A ticked drive is checked as soon as it is enabled, not at REC time.
  • Each backup drive is isolated: if it becomes unavailable (full, ejected, read-only), it is dropped with a message naming it and the take continues on the others.
  • If the destination drive is unplugged during the take, recording is stopped cleanly.
  • While recording, an alert appears as soon as an active drive falls below 10 GB free.
Destination checked before every take. VAREC refuses an unmounted volume (without this test, macOS would create a fake folder on the internal drive), then writes and deletes a test file — the only check that catches permissions, quotas and read-only volumes. A folder that does not answer within 3 seconds is never refused: a Start anyway button is offered, so that a slow drive does not cost a take.
Desktop fallback. If, despite the check, the folder cannot be created at REC time, VAREC records to the Desktop rather than lose the take, announces it with a permanent banner for as long as the situation lasts, and brings the TAKES tab, the Sound Report and the project back in line with the folder actually used.
False redundancy detected. A backup drive located on the same physical disk as the recording destination is dropped, with a warning visible on its card. Two volumes mounted from the same SSD protect against nothing: what matters is the failure of the physical disk.

Organisation on disk

Each session creates a {project}/{scene}/ folder in the destination and in every backup drive, with the same structure. The {project}.varec project file is saved in the destination's project folder.

11. Timecode

The clock at the top of the window shows the active source's timecode and, underneath, the current take's duration (in playback: position and take length).

TC card

Every timecode setting is gathered in the TC card of the bottom bar. A click on the card or on the clock opens its panel:

  • Current TC and status (age of the last frame received).
  • Source: Time of Day / Tentacle / LTC.
  • Frame rate and, for LTC, the input (Auto or a chosen channel).
  • Tentacle devices: Bluetooth scan and connection.

The card shows the reception state — synced, device detected or no signal — as “source · fps”. The settings are mirrored in Settings → Timecode. Source and frame rate are locked while recording.

LTC (Linear Timecode)

Receives LTC on an audio input of the interface. In Auto, VAREC searches for the signal on every input — patched channels first — and locks onto the one carrying it, with no manual setup; you can also force a channel. LTC is decoded even if the channel is neither armed nor patched. Automatic jam sync on signal loss, then resume.

Tentacle Sync E (Bluetooth)

Choose the Tentacle source, then 🔵 Scan…: every Tentacle in range is listed; click the one to use (Disconnect to release it). VAREC reads TC without a cable. It is the most practical option for light shoots.

For a lighter startup, the Bluetooth scan does not run at launch: it only starts on your first action (arming, monitoring, recording) when the source is Tentacle, or as soon as you choose it. The macOS Bluetooth permission prompt then appears at the relevant moment.

Time of Day (TOD)

Uses the system clock as the TC source. Ideal for documentary and news work, where syncing to real time simplifies post-production.

Frame rate

The frame rate (23.976 / 24 / 25 / 29.97 DF / 30 / 50 / 59.94 / 60 fps) is set in the TC card or in Settings → Timecode. It is written to the BWF header (TimeReference) and to the iXML block, ensuring compatibility with professional NLEs (Pro Tools, Avid, DaVinci Resolve, Reaper).

Clock drift. The audio interface's clock is not slaved to the timecode generator. At the end of a take, VAREC measures the gap between audio duration and TC duration and warns you if the drift becomes significant (beyond 100 ppm, about 360 ms per hour) — enough to explain a conform that slips.

12. Sound Report

The Sound Report is generated on demand from the METADATA tab, which shows a preview. It gathers all the information post-production needs.

Contents

  • Production header — project, date, production, sound engineer, contact, session folder, project notes.

13. VU meters, monitoring & analysis tools

VU meters are active as soon as the application opens: there is no need to arm a channel to check its inputs. Channels that are patched but not armed show their live level greyed out.

Metering modes

  • RMS + PPM — a wide RMS bar with a thin PPM needle on top. The classic broadcast mode.
  • Instant Peak — instantaneous peak level, ideal for spotting the slightest transient.

The clip indicator latches from 0 dBFS and the peak value switches to an alert colour. Peaks are held for 1 s, 3 s, 5 s or indefinitely (selector next to ↺ PEAK). The L and R sides of a stereo pair measure in exactly the same way. Bar and REC-frame animation is handled by the graphics card: the interface puts little load on the Mac, even during long takes.

Settings

ParameterChoices
StyleGradient or steps.
MeasurementRMS + PPM or Instant Peak.
Opacity15 to 100 % (no effect in waveform mode, where meters are already overlaid).
Rise (attack)From Instant to standard VU (300 ms).
Fall (release)From Instant (~8 ms) to Very slow (~2 s).
Refresh rateAuto (60 fps, 30 while recording — the rate at which levels arrive), 30 or 15 fps to save CPU.
Colour stepsThresholds and colours of the bar; the lowest step sets the bottom of the scale. Classic and Cold presets, Save as default.

All these settings are available via View → VU Meter… or Settings → Meters. In Auto mode, the frame rate only drops if the machine cannot keep up, whatever the track count.

Monitoring

The MONITOR button in the top bar turns the monitoring output on or off; the slider sets the volume.

  • Outside fader mode: with no solo, you hear the default track chosen next to the button (a stereo pair); with one or more solos, the soloed channels.
  • In fader mode: you hear the fader mix (or the MAIN MIX chosen as default track), and a solo is heard pre-fader.
  • Only armed and patched channels are audible. Monitoring works like a console: no channel cap, and changing solo rebuilds nothing.
  • Latency compensation (Settings → Audio): Auto, Manual (–500 to +500 ms) or Off.
Latency. Monitoring goes through the software chain. For zero-latency monitoring, use your audio interface's direct monitoring.

Analysis tools (solo mode)

Solo a channel to open the analysis suite. The five tools — Spectrum, Spectrogram, Peak, Loudness and ⊕ Phase — share a unified settings rail: settings on the left, canvas on the right. The ← → keys (↑ ↓ in vertical view) move from one tool to the next. Common settings: dB scale, time window (5 s to 1 min), spectrogram palette (Classic / Magma / Viridis / Grey / Heat) and a peak hold that can be turned off. On a stereo pair, the analysis source can be L / R / L+R.

Eco Mode. Eco mode hides the analysis tools — spectrum, spectrogram, peak, loudness, phase. The waveform and range playback remain available.

Detachable analysis window

The ⤢ button detaches the analysis panel into a separate, resizable, always-on-top window; it then disappears from the main window. A tool selector sits in its top bar, with a choice of analysed channel and a solo checkbox to follow the soloed channel.

Spectrum & spectrogram

The real-time FFT analyser shows a spectrum and a scrolling spectrogram in the chosen palette. Useful for spotting hiss, a stray frequency or a tonal imbalance.

  • Channel comparison: overlay another channel's curve to compare two sources.
  • Click-to-listen: click the spectrum to hear the frequency band under the cursor; the scroll wheel adjusts the filter's Q. Filtered listening also works in fader mode.

Phase alignment

The Phase tool measures the offset between two channels picking up the same source — two mics, a mic and a line feed, a lavalier and a boom — using GCC-PHAT correlation over 5 seconds of signal, with sub-sample accuracy. Range ±30 ms whatever the sample rate.

Choose a reference channel: both channels go into solo, panned to the centre (otherwise a polarity inversion would not be audible), and collection starts. When it ends, the offset is shown in milliseconds and samples with a confidence index; both waveforms are overlaid and zoomed onto a transient so you can check the alignment by eye. An inverted polarity is detected and flagged (Ø INVERSÉE).

Apply compensates the offset in monitoring (the leading channel is delayed); the Ø button inverts polarity. Both corrections are carried over to the files after the take, in a copy named …_DELAI±X.Xms / …_POL-Ø: the original is kept intact and the copy keeps its BWF/iXML metadata. Apply stays disabled until the measurement is deemed reliable. Explicit messages flag an unpatched channel, two channels on the same input or no signal.

Loudness tool (LUFS)

The Loudness tool measures perceived level according to BS.1770-4 / EBU R128 and shows the figures on the left and a large graph on the right (0 → −40 LUFS scale, target line and tolerance band, short-term curve coloured by deviation, integrated-level line):

  • Momentary (400 ms), Short-term (3 s), Integrated (gated), LRA (loudness range) and True-Peak.
  • Coloured Δ vs target, with 15 preset standards (EBU R128, ATSC A/85, ITU-R BS.1770, Spotify, YouTube, Apple Music, Amazon Music, Tidal, Deezer, SoundCloud, Netflix, AES streaming, podcast…) or a custom target. ↺ Reset intégré restarts the measurement.

14. Cloud sharing

VAREC can automatically send each take's files to a cloud service as soon as recording ends, without leaving the application. Only the destination's files are sent, not their backup copies, and the upload does not disturb the next take.

Supported providers

  • SwissTransfer (Infomaniak) — free, anonymous and hosted in Switzerland, no sign-up required. Up to 50 GB per transfer, link duration 1 / 7 / 15 / 30 days, up to 250 downloads, optional message and sender email.
  • Smash — API token; one share link per take. Ideal for quickly sending a take to post.
  • Dropbox — access token from a Dropbox app; direct-download links.
  • Cloudflare R2 — S3-compatible storage (Account ID, keys and bucket); presigned links valid for 7 days at most.
Beta. During the beta phase, cloud sending is unlocked for every tester. The former Frame.io and WeTransfer providers have been removed (APIs closed by their publishers).

Setup

  1. Click the ☁ CLOUD card in the bottom bar.
  2. Select the provider and enter its credentials — the ? button explains, step by step, where to get them.
  3. Tick automatic upload after each take.

Status

The cloud card always shows one of the following states:

Right-clicking the card always reopens the setup. Links are stored in the project and included in the Sound Report and the email.

15. Crash Recovery

VAREC is designed so that no power cut leads to lost files. This robustness rests on several complementary mechanisms.

Mechanisms

  • WAV headers (data chunk sizes) are updated continuously during recording — not just at the end —, on the destination as on backup drives.
  • The project file .varec is written atomically (written to a temporary file, then renamed).
  • The capture engine never waits: if it falls behind, the missing moment is replaced with silence at its exact place, the take stays locked to timecode, and the log shows how long was filled.
  • A watchdog detects a silent disconnection of the audio interface during recording.
  • In an emergency stop (interface disconnection, PortAudio error, unplugged drive), the files in progress are properly finalised — metadata written, files closed — and recording cannot silently carry on in the background.
  • The write mode is frozen at the start of the take. If the writing process disappears along the way, VAREC triggers an emergency stop rather than letting the take continue with no destination.
  • Native crashes (audio, CoreAudio, Bluetooth) are logged to logs/crash-native.log; an interface crash triggers a single automatic reload.

In the event of a power cut

Power cut, kernel panic, unplugged drive: the WAV files on disk remain readable up to the last block written. No recovery tool is needed.

Reliability test. Settings → Diagnostic → Reliability test measures audio buffer stability for 10 seconds, with no audio input required, along with the display refresh rate, the actual VU frame rate and its rendering cost. Useful for validating a machine before a critical shoot.

16. MIDI control

VAREC accepts transport and fader control over MIDI. Ideal for integrating VAREC with a control surface, a footswitch or a pedalboard in the control room.

Setup

  1. Open Settings → MIDI and click 🔍 Scan MIDI interfaces.
  2. Transport — choose the MIDI input and channel (or All). For each action (⏺ Record, ⏹ Stop, ▶ Play (monitor), ✂ Split), enter the note or CC, or click LEARN then press the control on your controller.
  3. Faders — choose the input, the MIDI channel and the base CC: the base CC drives channel 1, CC+1 channel 2, and so on.

A Stop received over MIDI stops the take immediately, without confirmation.

Tip. A MIDI footswitch assigned to REC/STOP keeps your hands free while recording — handy when capturing alone, without an assistant.

20. FAQ & Troubleshooting

No input channel detected

  • Check microphone permission in System Settings → Privacy & Security → Microphone.
  • Run detection again (🔍 in Settings → Audio) after connecting the interface.
  • For Dante VSC / SoundGrid interfaces: make sure the host service is running and the clock is synced.
  • Settings → Diagnostic → Run PortAudio diagnostic lists what the audio engine sees.

Dropouts or xruns while recording

  • Increase the buffer size (BUFFER card: 1024 → 2048 → 4096).
  • Use a fast drive: internal SSD, external USB 3 or Thunderbolt SSD. Avoid spinning drives beyond 16 channels.
  • Disable real-time antivirus scanning on the capture folder.
  • Turn on Eco Mode if you record a lot of channels, or cap the VU refresh rate at 30 or 15 fps.
  • Quit resource-hungry background applications.

“Recording destination unavailable”

  • Check that the drive is connected and mounted, and that it is neither full nor read-only.
  • Allow VAREC in System Settings → Privacy & Security → Files and Folders.
  • Choose another folder from the window offered, or record to the Desktop.

Timecode not received

  • Check that the frame rate is identical on the generator and in VAREC.
  • For Tentacle: make sure the Mac's Bluetooth is on and allowed for VAREC, then run Scan… again in the TC card.
  • For LTC: check the signal level on the input. Too low or clipped, it prevents decoding. Leave the input on Auto or force the right channel.

Do I need a licence during the beta?

No. During the beta phase, every feature is unlocked free of charge, with no activation, no account and no channel or time limit.

Does VAREC work with Dante / AVB / MADI?

Yes, as long as the interface is exposed by CoreAudio. That is the case for Dante Virtual Soundcard, RME MADI cards, Focusrite Red, Universal Audio Apollo, etc. On a Mac connected to a Dante network, VAREC can no longer freeze at launch.

Why 32-bit float?

32-bit float offers practically unlimited dynamic range (~1500 dB). You can no longer clip digitally: a transient at +20 dBFS remains fully recoverable in post without distortion.

What happens if my Mac crashes?

WAV files on disk remain readable up to the last block written, thanks to the continuous header updates. See §15 Crash Recovery.

Where are sessions stored?

Each session creates a {project}/{scene}/ folder in the recording destination and in every backup drive, holding the WAV files. The {project}.varec project file sits in the project folder.

Sending a crash report

Help → Send Crash Report menu: VAREC builds a ZIP archive of the last 14 days of logs and system information (version, system, processor, memory), then opens an email to support with the archive attached. Help → Show Log shows the live log.
